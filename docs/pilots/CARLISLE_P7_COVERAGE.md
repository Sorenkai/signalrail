## Blockers

### B-CE438 (unknown_signal_function, evidence: unknown)

CE438 stands at the inside node of cut-north-up-main, facing into play, and OSM gives it no railway:signal:<category> tag, so its function is unknown and movement never passes it (D-033). Every Up Main entry from the north (rt-um-fringe-ce336) stops there. P7: live OSM re-checked 2026-10-28 (node version 1, added 2024-06-03 in changeset 152204621 from Bing aerial imagery): still no category. The local SMART extract has a berth numbered 438 (a number match, I-005); a berth does not state a signal's function.

- **Records:** `osm-sig11954024796`, `rt-um-fringe-ce336`, `cut-north-up-main`
- **Needed:** A source stating CE438's function: an OSM category tag from survey, or a signalling plan
- **Proposed change:** If CE438 is a main signal, split rt-um-fringe-ce336 at it (fringe -> CE438, CE438 -> CE336); if it is a repeater or distant, no route change. Neither is assumed.
- **Groups:** `up-main-north-to-south` (72), `terminates-north-bays` (17)

### B-UPMAIN-UNTYPED (untyped_junction, evidence: unknown)

South of CE304 the Up Main passes osm-n2464365978 and osm-n13915496837: nodes with three edges and no railway=switch tag, so the importer creates no Points record and no game rule can configure them (D-029). P7: the physical connection is sourced (each is shared by the Up Main way 238574861 and a service=crossover way, 1526862397 and 1526862396, both added 2026-06-06 in changeset 183757649 from Bing aerial imagery; live OSM unchanged on 2026-10-28). A shared node shows a connection, not a switch type, toe or lie, and the local Network Rail GIS (licence unresolved) cannot say which parallel track each crossover joins. Typing them as switches would still be an inference, and would enable no service while B-CE438, B-CE268, B-CE263 and B-UPMAIN-DIAMOND remain.

- **Records:** `osm-n2464365978`, `osm-n13915496837`
- **Needed:** OSM railway=switch tagging of the two nodes (survey or imagery) and a re-import, or a signalling diagram
- **Proposed change:** After re-tagging and re-import: simple game rules for the two switches (Up Main leg normal, by convention, I-012 method) and Up Main routes CE304 -> CE285 -> CE278 -> ...; no change while the other four Up Main blockers remain.
- **Groups:** `up-main-north-to-south` (72)

### B-P1-INCOMPLETE (incomplete_junction, evidence: sourced)

Platform 1's only southern connection passes osm-n1460504022, tagged railway=switch but mapped with two edges (D-025), so movements through it are unresolved. P7, from the OSM element histories (api.openstreetmap.org, read 2026-10-28): the missing third leg was Siding A (way 132760240), which ended at this node from 2011 until version 12 (2025-07-26). Changeset 178027337 (2026-02-02, citing the National Electronic Sectional Appendix as its source) cut Siding A back to the double slip osm-n1460504024, and changeset 178027702 extended it to the dead end osm-n13520580940. The railway=switch tag dates from a 2020 bulk edit that tagged nodes with three or more ways (changeset 84719872). So the two mapped legs are the platform 1 track and the toe towards osm-n1460504059, which do connect; whether points still exist there conflicts between sources (OSM 2026: the siding connection removed; the local Network Rail GIS, 2024 geometry, licence unresolved: a three-way node 1.1 m away). No OSM signal is mapped on platform 1, and the local SMART extract has a station berth numbered 301 with no OSM signal.

- **Records:** `osm-n1460504022`, `osm-w132761142-1`, `osm-n1460504024`
- **Needed:** Confirmation of whether points remain at osm-n1460504022 (survey, current imagery or a signalling plan), an OSM correction and re-import; and a source for platform 1's signals
- **Proposed change:** If the points are gone: retag the node in OSM (removing railway=switch) and re-import, which makes it plain track. If they remain: an OSM correction restoring the leg. Either way a platform 1 route also needs its platform signals sourced; none is authored on an incomplete junction or past a probably unmapped signal.
- **Groups:** `platform-1-down` (21), `cumbrian-through` (1)
